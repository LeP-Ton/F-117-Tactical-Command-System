# 废案：AI DEBUG 与解谜体验融合方案

## 状态说明
- 状态：已废弃。
- 废弃原因：`SIGINT OVERLAY` 的作用不够明显，有限情报动态效果没有形成清晰、可感知的战术价值。

## 原始 Plan 全文

# AI DEBUG 与解谜体验融合方案

## 总结

- 普通游戏不再公开显示全知 `AI DEBUG` 开关。
- 默认启用基于有限情报的动态态势层，让玩家和直播观众看到雷达搜索、风险变化与受照射反馈，但不泄露真实雷达状态或敌方判断。
- 完整全知视图仅保留为开发入口。

## 核心改动

- 新增玩家态势层 `SIGINT OVERLAY`
  - 根据已发现的 `radarIntel` 绘制估计雷达位置、估计覆盖和动态扫描扇区。
  - 扫描角度由雷达代号和任务时间生成，与真实雷达扫描角度无关，并使用虚线、低透明度及 `EST` 标识表达不确定性。
  - 根据估计覆盖、位置误差和情报等级生成玩家侧威胁热区；多个估计覆盖重叠时风险增强。
  - 未定位雷达信号只影响右侧情报数量，不在地图上生成虚假精确位置。

- 增强受照射反馈
  - 根据玩家已经获得的 `THREAT WARNING` 阶段，在飞机周围显示脉冲或地图边缘告警。
  - 强度跟随跟踪进度，颜色依次区分疑似搜索、持续跟踪、锁定和导弹来袭。
  - 不显示雷达来源方向，避免从视觉效果反推出真实雷达位置。

- 玩家显示控制
  - 地图按钮由 `AI DEBUG` 改为 `SIGINT OVERLAY ON/OFF`，默认开启。
  - 关闭后仍保留当前静态有限雷达情报；开启仅增加动态估计效果，不增加真实信息。
  - 地图图例明确使用“威胁估计 / 雷达情报”，不出现 Debug、Belief、Contact 等内部术语。

- 全知调试视图
  - 真实雷达位置、真实扫描角度、Radar Contact、敌方 Belief、Commander 目标及 Utility 继续保留。
  - 普通 GitHub Pages 界面不显示入口。
  - 仅在开发环境或显式 `?ai-debug=1` 参数下显示 `AI DEBUG` 控制。
  - 调试状态不写入游戏存档，也不改变任何任务数据。

## 接口与数据边界

- `TacticalMap` 分离两个显示状态：
  - `showThreatEstimate`：玩家有限情报动态层。
  - `showAiDebug`：开发者全知层。
- 新增纯计算模块，从 `RadarIntelReport[]` 生成威胁估计网格；接口不得接收真实 `radars`、`radarContacts` 或 `beliefMap`。
- 绘制优先级为：玩家估计层 → 开发调试层；开启调试时隐藏玩家估计图形，避免两套扫描线叠加。
- 不修改雷达探测、Commander、任务难度、Seed 或存档结构。

## 测试与验收

- 普通模式下画面持续显示估计扫描与风险热区，但估计扫描角度不等于真实扫描角度。
- 情报中没有定位信息时，地图不绘制对应雷达位置或覆盖范围。
- 情报精度提高后，热区和扫描范围更集中；低精度情报呈现更大的不确定区域。
- 雷达估计覆盖重叠区域风险高于单雷达区域。
- `SIGINT OVERLAY` 开关不改变任务状态、探测结果或 Campaign 进度。
- GitHub Pages 默认不出现 `AI DEBUG`；开发环境和 `?ai-debug=1` 可恢复现有完整调试能力。
- 普通模式代码路径无法读取真实雷达、Contact 或 Belief 数据。
- 运行 `npm run typecheck`、`npm run test` 和 `npm run build`，并补充威胁估计纯函数与显示权限测试。

## 默认假设

- `SIGINT OVERLAY` 默认开启，以保证首次游玩和直播画面具备动态表现力。
- 玩家与直播观众观看同一界面，不建设独立观战窗口。
- 当前本地未提交的侧栏 UI 优化作为实施基础保留，不覆盖或回退。

## 废弃原因

- `SIGINT OVERLAY` 开启与关闭后的差异不够明确，玩家难以直接判断它提供了什么信息。
- 风险热区与现有雷达估计范围的表达重复，没有产生足够清晰的新决策价值。
- 虚拟扫描角度不是敌方真实状态，也不直接参与任务结果，容易被理解为装饰效果。
- 新增常驻开关增加了界面理解成本，却没有相应提升解谜体验或演示效果。
