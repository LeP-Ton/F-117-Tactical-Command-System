## 关键设计结论

- 游戏的长期构筑对象是后续战场条件，而不是 F-117 本体数值。
- INTEL、STRIKE、SEAD、COMMAND STRIKE 分别作用于信息、时间、空间和协同四个维度。
- Enemy Alert 是跨任务持久战略警戒；Awareness 是单任务 Commander 输入；THREAT WARNING 是针对飞机的交战进度。
- OPERATION CODE 只固定基础世界；最终任务还需要相同 Run 历史、航线操作和时间演进才能完整复现。
- 当前天气预报是任务创建时生成的 T+30/60/90 秒绝对时刻快照，不是滚动预报。
- 当前生成器只有撤离净空和目标火控覆盖等局部公平性约束，没有严格的数学可通关证明。
- 一级 INTEL 的主要机制收益是补齐雷达和消除坐标误差；当前已定位报告的类型标签本身与真实类型一致。

+### 3.1 网络结构

-- `COMPLETED`：任务成功，可进入复盘。

+- `LOCKED`：尚未获准执行，但可以查看按当前 Run 状态生成的只读任务预览。

+- `FAILED`：上次执行失败，仍可重新规划并执行。
 - `EXPIRED`：同层另一任务成功后关闭。

-| 任务 | 持久效果 |
+任务网络顶部的 `RADAR COVERAGE` 只显示 SEAD 形成的持久覆盖修正，不包含 Enemy Alert 的放大倍率。例如 `RADAR COVERAGE 90%` 与 `ENEMY ALERT 10` 会共同产生 `0.9 × 1.04 = 93.6%` 的基础范围结果。
+
+Enemy Alert 不等于任务内 Awareness，也不等于玩家看到的 THREAT WARNING：
+
+| 状态 | 生命周期 | 作用 |
+|---|---|---|
+| Enemy Alert | 跨任务 | 放大后续雷达范围并触发最终战警戒增援 |
+| Awareness | 单任务 | 驱动 Commander 选择监视、协同搜索或集中搜索 |
+| THREAT WARNING | 单任务、针对飞机 | 显示跟踪质量、锁定和导弹来袭 |
+
+## 5. 地图系统与任务准备
+
+### 5.1 固定边界
+
+- 世界坐标固定为 `1000×1000 u`，网格间隔 `100 u`。
+- F-117 插入点固定为 `(90, 850)`。
+- 撤离区固定在东北区域 `(850, 30, 120×120)`。
+- 目标生成在地图中上部，坐标范围为 `x=400–790、y=100–390`。
+- 雷达中心不得进入撤离区边界外扩 `80 u` 的净空区，但探测范围可以覆盖撤离区。
+- 最终准备完成后，至少一部 Fire Control 必须完整覆盖目标 `58 u` 攻击区，并额外保留 `20 u` 范围余量。
+
+撤离区净空避免雷达本体与出口重叠，目标区火控约束则保证每场任务都有最低防御压力。后者只保证飞机攻击时处于某部火控雷达真实范围内，并不保证波束一定命中或探测一定成功。
+
+### 5.2 Seed 生成内容
+
+每个节点的基础任务内容包含：
+
+| 元素 | 生成规则 |
 |---|---|
-| INTEL | 一次完成核实全部雷达坐标与型号，两次完成授权 `TOTAL INTEL`；不再维护额外的情报质量百分比 |
-| STRIKE | 将后续任务的雷达扫描速率乘以 90%；两次累计为 81%，同时影响扫描动画与真实 Sensor 周期 |
-| SEAD | 将后续雷达覆盖范围乘以 90%，最低为 55%；不影响扫描速度或最终火控增援 |
-| COMMAND STRIKE | 将后续 Commander 协调降至 65%，削弱跨雷达 Contact 共享和联合跟踪能力 |
-| FINAL STRIKE | 根据整个 Run 历史组装最终防空体系，成功后赢得本次 Run |
+| Terrain | 2–4 个静态山地区域；位置、宽高和探测倍率由 Seed 决定 |
+| Weather | 1–2 个动态气象单元；类型、位置、尺度、速度、强度、相位和周期由 Seed 决定 |
+| Radar | 3–5 部，按 Early Warning → Acquisition → Fire Control 循环生成 |
+| Target | 地图中上部的固定类型目标 `COMMAND-BUNKER` |
 
-所有任务成功都会使 Enemy Alert 增加 2，失败增加 10；Alert 会按 `1 + Alert / 250` 扩大后续雷达范围。Enemy Adaptation 还会分析已经发生的飞行轨迹，针对地形利用、南北走廊和直达路线调整后续雷达部署；它不会读取尚未执行的未来航点。
+基础内容生成后，任务准备按以下顺序组合当前 Run 状态：
 
-这些奖励分别改变不同维度：INTEL 改变玩家掌握的信息，STRIKE 改变雷达扫描频率，SEAD 改变覆盖空间，COMMAND STRIKE 改变雷达网协同。任务类型不会强化 F-117 本体，也不会绕过“摧毁目标并撤离”的统一成功条件。
+1. 生成节点的基础任务。
+2. 使用 SEAD 修正与 Enemy Alert 修正调整基础雷达范围。
+3. 根据 Enemy Adaptation 移动需要反制的雷达。
+4. Final Strike 节点追加最终防御雷达。
+5. 执行撤离区净空和目标区 Fire Control 覆盖校验。
+6. 基于最终真实雷达部署重新生成玩家侧有限情报。
+7. 写入 STRIKE 扫描速率与 COMMAND STRIKE 指挥链效率。
 
-## 有限情报与 INTEL 权限
+所以，同一节点的基础地形、天气、雷达和目标由 Seed 固定，但最终雷达位置、范围与数量还取决于当前 Run 历史。锁定节点预览标记为 `CURRENT ESTIMATE`，后续完成其他任务后再次查看时可以发生变化。
 
-普通地图显示的是玩家掌握的雷达情报，而不是敌方真实状态：
+当前生成器没有执行完整的“数学可通关证明”。它提供撤离净空和目标火控等局部公平性约束，但极端 Seed 仍可能形成非常困难的组合；这属于当前设计边界，而不是已实现的路径可达性保证。
 
-- 未完成 INTEL 时，每部雷达有 90% 的确定性发现概率。
-- 估计位置带有 `50–70 u` 的误差半径，覆盖范围存在 `±8%` 估算误差。
-- 情报置信度固定落在 60%–88% 区间；`POSSIBLE` 信号不提供范围估计。
-- 未定位信号只显示数量，不生成虚假精确坐标。
+## 6. OPERATION CODE 与确定性随机
 
-以上有限情报规则参数对所有任务一致，但每部雷达的遗漏与误差由任务 Seed 独立决定，因此相同 OPERATION CODE 与 Run 历史仍可复现。游戏不再维护会被权限层级覆盖的连续“情报质量”数值。
+`OPERATION CODE` 是整个 Run 的根 Seed，作用类似 Minecraft 世界种子，但使用项目自己的轻量算法：
 
-INTEL 权限由已完成的 INTEL 节点数量派生：
+```text
+字符串 OPERATION CODE
+  → FNV-1a 32 位哈希
+  → Mulberry32 伪随机序列
+  → 任务网络节点 Seed：<CODE>:C<层>-<序号>
+  → 任务内容 Seed：<节点 Seed>:MISSION-CONTENT
+```
 
-- `0/2`：有限雷达情报。
-- `1/2`：后续任务准确显示全部雷达位置和类型，但不公开真实范围或敌方内部状态。
-- `2/2`：正式解锁 `TOTAL INTEL`，可显示真实雷达扫描、Contact、Belief Map、Commander 目标和 Operator Utility。
+不同系统使用独立命名子 Seed，避免新增一次随机读取后扰乱其他系统：
 
-开发环境或显式 `?ai-debug=1` 同样可以打开完整内部视图，但显示开关不改变任何任务计算或存档结果。
+- 雷达有限情报：`<节点 Seed>-M01:INTEL:<Radar ID>`。
+- 天气预报误差：`<节点 Seed>:FORECAST:<Weather ID>:<任务秒数>`。
+- Final Strike 增援：`<节点 Seed>-M01:FINAL-DEFENSE`。
+- 雷达探测判定：`<节点 Seed>-M01:<Radar ID>:<Scan Count>`。
 
-## 雷达与防空交战
+相同 OPERATION CODE 只保证相同的基础世界。完整复现还要求相同游戏版本、任务选择、失败次数、Enemy Alert、情报权限、历史航迹、航线操作和任务时间演进。
 
-防空网由三类具有真实差异的雷达组成：
+## 7. 有限情报与 INTEL 权限
 
-| 类型 | 主要职责 | 特性 |
-|---|---|---|
-| Early Warning | 远程预警 | 覆盖大、波束宽，Contact 精度和火控贡献较低 |
-| Acquisition | 搜索与目标获取 | 覆盖、扫描和跟踪能力均衡 |
-| Fire Control | 近程火控与制导 | 覆盖较小、波束窄，但扫描快、Contact 精度和锁定贡献高 |
+### 7.1 Tier 0：固定有限情报
+
+未完成 INTEL 时，每部真实雷达独立生成一份战前报告：
+
+- 90% 概率被定位；未定位目标只计入“未定位信号”。
+- 已定位雷达的位置误差半径为 `50–70 u`。
+- 覆盖范围估算误差为真实范围的 `±8%`。
+- 置信度为 60%–88%，划分为 `POSSIBLE / PROBABLE / CONFIRMED`。
+- `POSSIBLE` 没有可靠的范围估算。
+
+当前实现中，已定位报告显示的雷达类型标签与真实类型一致，但仍属于战前识别信息；第一次 INTEL 的主要机制收益是补齐全部雷达并消除坐标误差，而不是改变探测算法。
+
+### 7.2 Tier 1：雷达识别核实
+
+完成一次 INTEL 后：
+
+- 后续任务报告包含全部真实雷达，不再存在遗漏。
+- 雷达位置替换为真实坐标，位置误差归零。
+- 雷达类型转为已核实状态，地图不再保留未知问号。
+- 原报告已有的范围估算继续保留；原先没有可靠范围的雷达仍不显示真实范围。
+- 不显示实时扫描角度、Radar Contact、Belief、Commander 或 Operator 内部状态。
+
+### 7.3 Tier 2：TOTAL INTEL
+
+完成第二次 INTEL 后，正式解锁可开关的 `TOTAL INTEL`，并在进入后续任务时默认开启：
+
+- 显示雷达真实位置、真实范围、类型和实时扫描线。
+- 显示敌方 Radar Contact 及误差圈。
+- 显示 Belief Map 概率热区和 Commander 推测目标。
+- 显示 Awareness、Commander 意图与 Utility。
+- 显示每部 Radar Operator 的模式及 W/S/F Utility。
+
+雷达没有开关机状态，所有雷达始终参与扫描。`TOTAL INTEL` 是观察权限，不写入任务存档开关，也不改变真实雷达、Contact、Commander、交战或任务结算。
+
+开发环境或显式 `?ai-debug=1` 参数可以绕过任务网络权限显示同一内部视图，用于调试；正式奖励和开发入口共用显示能力，但授权来源不同。
+
+## 8. 雷达系统
+
+### 8.1 三类雷达的职责
+
+| 类型 | 范围 | Sensor 周期 | 广域角速度 | 波束 | 探测倍率 | Contact 精度 | 火控贡献 |
+|---|---:|---:|---:|---:|---:|---:|---:|
+| Early Warning | 380–470 u | 0.40 s | 28°/s | 36° | 0.82× | 0.72× | 0.55× |
+| Acquisition | 270–360 u | 0.25 s | 38°/s | 24° | 1.00× | 1.00× | 1.00× |
+| Fire Control | 180–260 u | 0.16 s | 52°/s | 12° | 1.18× | 1.35× | 1.50× |
+
+- Early Warning 用宽波束和远距离产生早期线索，但单次证据不适合快速完成火控链路。
+- Acquisition 在覆盖、精度和跟踪之间居中，适合维持目标获取并向网络提供共享 Contact。
+- Fire Control 覆盖较小、波束最窄，但扫描、Contact 精度和锁定贡献最高。一旦被 Commander 或共享 Contact 引导到正确方位，它会快速建立高质量跟踪。
+
+任何类型都可以依靠自身 Contact 推进跟踪和交战；Fire Control 不是唯一能够达到 `LOCKED` 或触发导弹的雷达，只是效率最高。
+
+### 8.2 探测判定
+
+雷达只有同时满足真实范围和波束方向条件时才计算非零探测概率。单次概率由以下因素相乘：
+
+```text
+基础概率 0.46
+× 雷达类型倍率
+× 距离因子
+× 飞机朝向因子
+× 所有命中地形倍率
+× 所有命中天气倍率
+× 波束命中因子
+```
 
-雷达不是“进入覆盖圈即发现”。只有扫描波束经过飞机且概率判定成功时才会生成带误差的 Radar Contact。探测概率受距离、机体朝向、地形遮蔽和动态天气共同影响。
+最终概率上限为 95%。距离越接近范围边缘，概率越低；超过范围或不在当前波束中时概率为零。侧面对雷达的风险高于机头或机尾朝向雷达。
 
-STRIKE 的扫描速率修正同时作用于广域旋转速度、扇区摆扫相位和实际扫描周期。速率为 90% 时，波束角速度为基础值的 90%，实际扫描间隔变为 `基础周期 / 0.9`；它不会改变单次扫描的探测概率、覆盖范围或 Contact 精度。
+探测成功生成的是带误差的 Radar Contact，不是飞机真值。Contact 包含估计位置、置信度、信号强度、误差半径和火控贡献，并在 8 秒后从活动列表移除。
 
-每台 Radar Operator 根据自身或共享 Contact，在以下模式间选择 Utility 最高的动作：
+### 8.3 STRIKE 如何影响雷达
 
-- `WIDE_SEARCH`：360° 广域搜索。
-- `SECTOR_SEARCH`：围绕可疑方位扇区摆扫。
-- `FOCUSED_TRACK`：聚焦最近的高质量 Contact。
+STRIKE 的扫描速率修正同时作用于：
 
-连续证据会推动 `UNDETECTED → SUSPECTED → TRACKED → LOCKED → MISSILE_INBOUND`。没有新 Contact 时跟踪质量下降；导弹来袭后必须在倒计时结束前切断足够多的新证据，否则飞机被摧毁。
+- `WIDE_SEARCH` 的旋转角速度。
+- `SECTOR_SEARCH` 的摆扫相位。
+- Radar Sensor 的真实判定周期。
 
-每场任务最终准备完成后都会校验：至少一部 Fire Control 完整覆盖目标攻击区并保留 `20 u` 余量。该约束保证目标区存在火控威胁，但不保证飞机一定被发现。
+速率为 90% 时，实际扫描间隔为 `基础周期 / 0.9`。它不会缩小覆盖、改变波束宽度、提高单次隐身效果或降低 Contact 精度；收益来自单位时间内更少的扫描机会。

-## 环境、天气与航线成本
+### 9.2 Radar Operator
 
-- Terrain 是静态山地遮蔽区。
-- Weather Cell 由 Seed 生成，并随任务绝对时间确定性移动、改变范围、强度和类型。
-- Cloud、Fog、Rain、Storm 分别使飞机减速 10%、15%、20%、30%；重叠时只取最强减速。
-- 规划阶段提供带误差的 `T+30/60/90s` 天气预报。
-- 相同 Seed 与相同任务时间会复现相同地图、雷达、目标和真实天气状态。
+每部雷达每 0.5 秒重新计算三种动作的 Utility，选择得分最高者：
 
-恶劣天气和地形能够降低探测概率，但天气减速也会延长雷达覆盖内的暴露时间。安全航线因此不是简单绕开所有覆盖，而是在情报误差、油量、遮蔽和任务时间之间求解。
+- `WIDE_SEARCH`：没有近期证据时进行 360° 广域旋转。
+- `SECTOR_SEARCH`：围绕近期 Contact 或 Commander 指定方位进行约 ±42° 摆扫。
+- `FOCUSED_TRACK`：在最近 4.5 秒证据足够强时直接指向估计方位。
 
-## 地图与任务生成
+活动 Contact 最长保留 8 秒。Operator 优先使用本雷达 Contact；没有本地证据时，可以在指挥链允许的共享窗口内使用全网最新 Contact。
 
-战术地图坐标系固定为 `1000×1000 u`，网格间隔 `100 u`。插入点、东北撤离区和目标区火控覆盖规则构成稳定边界，其余主要内容由任务 Seed 生成：
+### 9.3 Belief Map
 
-| 内容 | 当前生成规则 |
-|---|---|
-| 地形 | 2–4 个静态山地区域；位置、宽高和探测遮蔽系数由 Seed 决定 |
-| 天气 | 1–2 个动态单元；初始类型、位置、尺度、速度、强度、演化相位和周期由 Seed 决定 |
-| 雷达 | 3–5 部，按 Early Warning → Acquisition → Fire Control 顺序循环生成，保证普通任务至少包含三种类型 |
-| 目标 | 在地图中上部生成；进入 `58 u` 攻击半径后自动投弹 |
-| 撤离区 | 固定在东北区域；雷达中心必须与其边界保持 `80 u` 净空，但雷达覆盖可以延伸至撤离区 |
-| 有限雷达情报 | 每部雷达按固定基线和独立子 Seed 生成遗漏、`50–70 u` 位置误差与 `±8%` 范围误差 |
+Belief Map 使用 `24×24` 概率网格融合所有新 Contact：
+
+- Contact 的位置误差按空间概率注入，而不是当作单点真值。
+- 连续观测用于估计运动方向。
+- 失联后概率沿估计速度传播，同时扩散和衰减。
+- 证据过旧或总概率过低时，Belief 会失效，Commander 不再获得可靠目标位置。
+
+热力图表达的是“敌方认为飞机可能在哪里”，不是额外的真实探测范围。
+
+### 9.4 单任务 Awareness
+
+Awareness 是任务内 `0–100` 的总体警戒：
+
+- `CALM`：0–17。
+- `SUSPICIOUS`：18–41。
+- `SEARCHING`：42–71。
+- `HUNTING`：72–100。
+
+新 Contact 按置信度和信号强度提高 Awareness；没有证据时每秒下降 0.22。投弹额外增加 34。Awareness 只影响 Commander 搜索意图，不直接等于对飞机的火控锁定。
+
+### 9.5 Air Defense Commander
+
+Commander 在 100% 指挥链效率下每秒评估一次 Awareness、有效 Belief 与雷达状态：
+
+- `MONITOR`：提高广域搜索倾向。
+- `COORDINATED_SEARCH`：提高扇区搜索倾向，并让多部雷达以错开的方位覆盖可疑区域。
+- `CONCENTRATE_SEARCH`：提高聚焦跟踪倾向。
+
+COMMAND STRIKE 把后续协调效率乘以 65%。效率降低会：
+
+- 按反比延长 Commander 决策间隔。
+- 按比例缩短跨雷达 Contact 共享窗口。
+- 降低 Commander 对 Operator Utility 的偏置强度。
+- 增大围绕 Belief 目标分配搜索方位时的误差。
+- 降低额外雷达证据形成联合跟踪的贡献。
+
+它不会关闭雷达、降低单部雷达基础探测概率或取消本地火控能力。
+
+## 10. 防空交战与 THREAT WARNING
+
+新 Contact 会累积 `0–100` 跟踪质量：
+
+- `UNDETECTED`：0–15。
+- `SUSPECTED`：16–41。
+- `TRACKED`：42–71。
+- `LOCKED`：72–99。
+- `MISSILE_INBOUND`：达到 100 后发射导弹。
+
+最强 Contact 代表单部雷达的本地火控贡献；其余 Contact 作为联合跟踪证据，按指挥链效率缩放。没有新 Contact 时，跟踪质量每秒下降 14。
+
+导弹飞行时间为 8 秒。倒计时期间若跟踪质量降到 32 以下，导弹失去制导并判定规避成功；倒计时结束仍保持制导则命中飞机。命中没有第二次随机判定，结果取决于玩家能否通过转向、脱离覆盖或进入遮蔽切断新证据。
+
+`THREAT WARNING` 是玩家可用的模糊告警，只给出当前阶段、跟踪进度与导弹倒计时，不泄露具体雷达来源方向。
+
+## 11. 地形与动态天气
+
+### 11.1 Terrain
+
+Terrain 是静态矩形山地区域，不移动、不改变类型。飞机位于区域内时，该区域的探测倍率参与雷达概率计算；重叠地形会乘法叠加。Terrain 不直接改变飞机速度或燃油。
+
+### 11.2 Weather Cell
+
+Weather 与 Terrain 分离建模。每个 Weather Cell 保存初始类型、原点、基础尺度、速度、基础强度、演化相位和周期，当前状态由“初始参数 + 任务绝对时间”纯函数推导，因此不受帧率影响。
+
+天气会：
+
+- 按速度持续移动，并越过地图边界循环进入。
+- 在 `Cloud → Rain → Storm → Rain → Fog` 序列中演化。
+- 随强度周期改变范围大小与探测衰减。
+- 根据当前类型降低飞机速度。
+
+| 天气 | 飞行速度损失 | 探测影响 |
+|---|---:|---|
+| Cloud | 10% | 较弱至中等遮蔽 |
+| Fog | 15% | 中等遮蔽 |
+| Rain | 20% | 中等至较强遮蔽 |
+| Storm | 30% | 通常遮蔽最强 |
+
+多个 Weather Cell 重叠时，探测倍率乘法叠加；飞行减速只取最强的一项，避免速度异常连乘。天气不会增加单位距离油耗，但会延长任务时间和雷达覆盖内暴露时间。
+
+### 11.3 固定时刻天气预报
+
+任务创建时生成一次出动前预报，描述任务绝对时刻 `T+30/60/90s` 的预计类型、区域、尺度趋势和可信度：
+
+- 预报位置和尺度带有 Seed 固定误差。
+- 时刻越远，位置误差越大、可信度越低。
+- 它不是以玩家当前时刻为零的滚动预报。
+- 任务运行到对应绝对时刻后，该条预报从侧栏和地图隐藏；系统不会把已经过去的轮廓继续当作未来情报。
+
+这种设计让玩家在出动前安排与气象单元的会合时机，同时保留预测误差和执行中信息衰减。
+
+## 12. 航线、速度与燃油
+
+- F-117 基础速度为 `3.6 u/s`。
+- 满油可飞行距离为 `2000 u`，等于地图两条边之和。
+- 燃油按飞机每个 Tick 的真实累计位移扣减，不按航线首尾直线估算。
+- 天气改变当前速度，但不改变单位距离燃油消耗。
+- 剩余燃油不足以完成当前 Tick 时，飞机只移动到剩余航程终点并失败。
+
+左侧航点面板分别显示：
+
+- 规划总航程：当前完整航点折线总长。
+- 剩余航程：从飞机当前位置经过所有未完成航点的长度。
+
+规划总航程不自动包含目标和撤离区；玩家必须主动把航点引导进目标攻击半径和撤离矩形。
+
+## 13. Enemy Adaptation：基于已飞航迹的反制
 
-任务生成完成后依次应用 Enemy Alert、SEAD 覆盖修正、STRIKE 扫描修正、COMMAND STRIKE、Enemy Adaptation 和 Final Strike 增援，最后执行撤离区净空与目标区 Fire Control 覆盖校验，并基于最终真实雷达重新生成玩家侧有限情报。因此同一节点在 Run 早期预览和真正解锁后，基础地图相同，但防空部署可能因玩家此前行动而改变。
+敌方适应只分析已经飞过的轨迹，不读取当前或未来计划航点。航迹按至少 `20 u` 位移采样，并形成三项加权画像：
 
-## OPERATION CODE 与确定性生成
+- 地形利用：采样点位于 Terrain 内的比例达到 35%。
+- 南北航路：平均纵向位置偏离地图中线达到 8%。
+- 直达倾向：起终点直线距离与实际航程之比达到 72%。
 
-`OPERATION CODE` 是整个 Run 的根 Seed，作用类似 Minecraft 的世界种子：相同字符串与相同游戏版本会生成相同的任务网络和基础任务内容，但本项目使用自己的轻量算法，并非 Minecraft 的生成算法。
+成功任务按 `1.0` 权重更新画像，失败按 `0.5`。识别一、二、三项显著特征时，雷达反制移位强度分别为 22%、32%、42%；没有显著特征时不进行适应性移位。
+
+每项特征选择空间上最接近相应反制位置、且尚未用于其他反制的雷达：
+

+- 南北航路显著：向对应走廊移动雷达。
+- 直达倾向显著：向插入点与目标之间的直达轴线移动雷达。
+
+距离目标最近、承担固定目标防御的 Fire Control 不参与适应性移位。玩家可以通过改变路线模式规避反制，也可以故意制造历史偏好诱导后续错误部署。
+
+## 14. Final Strike 防御组装
+
+最终任务不是普通节点换名，而是基础任务与整个 Run 历史的汇总：
+
+1. 固定增加目标区 `FINAL-GUARD` Fire Control。
+2. Enemy Alert ≥ 15 时增加 `ALERT-GUARD` Early Warning。
+3. 累计观察权重至少为 2 且形成至少两项显著画像特征时，增加 `ADAPT-GUARD` Acquisition。
+4. STRIKE 扫描修正作用于最终战全部雷达，包括增援。
+5. SEAD 覆盖修正保留，但不会阻止 `FINAL-GUARD` 上线。
+6. COMMAND STRIKE 继续削弱最终战指挥链。
+7. INTEL 权限决定玩家能以何种精度观察最终部署。
+8. 最后重新执行撤离净空、目标火控覆盖和有限情报生成。
+
+`FINAL DEFENSE BRIEFING` 会列出已经触发的防御变化，但新增雷达仍服从玩家当前情报权限，不会因为是增援就自动暴露真实位置。
+
+## 15. 预览、复盘与持久化
+
+### 15.1 预览任务
+
+所有锁定节点都可以进入只读任务预览。预览与正式出击共用任务准备函数，因此会反映当前 Enemy Alert、已完成任务和 Enemy Adaptation，但不会：
+
+- 创建或修改当前 Mission。
+- 添加、移动或删除航点。
+- 提前结算任务或改变任务网络。
+
+### 15.2 复盘任务
+
+成功进入撤离区的同一 Tick 会冻结快照，包括最终飞机状态、航线、已飞轨迹、天气、雷达、Contact、Belief、Commander、Operator、Seed、任务时间和当时情报权限。
+
+- 任务视角：还原成功时玩家拥有的信息权限。
+- 全景复盘：显示冻结的真实雷达和敌方内部状态，不受当时 INTEL 权限限制。
+
+复盘只读取历史快照，不重新运行雷达或天气，也不会改变当前 Run。
+
+### 15.3 浏览器存档
+
+Run、任务网络、当前 Mission 和成功复盘每秒保存到浏览器 `localStorage`，页面关闭前还会再次保存：
+
+- 刷新运行中任务后继续执行，不生成暂停状态。
+- 旧版 `PAUSED` 存档会迁移为 `RUNNING`。
+- 旧版连续情报质量字段会在恢复时剥离。
+- 当前只有单 Run 本地存档，没有多存档槽或云同步。
+
+## 16. 音效与事件
+
+音效由领域事件驱动，通过原生 Web Audio API 合成：
+
+- Radar Contact、Awareness 提升、投弹和目标爆炸使用短音效。
+- 火控锁定和导弹来袭使用可清理循环音。
+- 脱锁、任务结束或组件卸载时必须停止循环警报。
