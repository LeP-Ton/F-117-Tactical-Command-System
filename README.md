# F-117 Tactical Command System（F-117 战术指挥系统）

以 F-117 隐身攻击机为主题的解谜与动态规划军事模拟游戏。玩家不是直接驾驶飞机，而是在有限情报下规划航线，并在任务持续执行时调整未来路径，穿越由雷达、天气、地形和敌方指挥系统共同形成的动态防空网络。

- 在线版本：<https://lep-ton.github.io/F-117-Tactical-Command-System/>
- 完整规则与数值：[游戏机制手册](docs/game-mechanics.md)
- 技术栈：React 18、TypeScript、Vite、HTML Canvas、Vitest

## 开发与发布

```bash
npm install
npm run dev
```

提交前验证：

```bash
npm run typecheck
npm run test
npm run build
```

`main` 分支由 GitHub Actions 构建并发布至 GitHub Pages。Vite 使用相对资源基址，因此构建结果可以运行在仓库子路径。

## 核心玩法

一次任务包含以下阶段：

1. 在任务网络选择“规划任务”；未解锁节点只能“预览任务”。
2. 在战术地图添加、拖动、排序航点，并结合有限雷达情报和天气预报制定航线。
3. 确认航线后任务持续执行，不支持暂停、重置或中途返回任务网络。
4. 飞行中仍可新增航点，并移动、删除或排序当前目标航点之后的路径；当前目标和已飞路径保持锁定。
5. F-117 进入目标攻击半径后自动投放武器，随后必须进入东北撤离区。
6. 只有目标摧毁且成功撤离才会完成节点；飞机损失、燃油耗尽或航线结束时未满足目标都会失败。
7. 失败节点可重新规划或改选同层任务；成功任务会保存撤离瞬间快照，可从任务网络“复盘任务”。

飞机基础速度为 `3.6 u/s`，满油航程为 `2000 u`。燃油按实际飞行距离消耗，天气只改变速度和暴露时间，不额外改变单位距离油耗。

顶部“操作说明”提供游戏内简明规则入口。任务执行期间打开说明不会停止飞机或敌方系统，因此界面会显示“任务执行中 // 飞行控制持续生效”。

## 任务网络

每个 Run 由三个顺序二选一阶段和一个 Final Strike 组成。节点状态包括：

- `AVAILABLE`：可以规划并执行。
- `LOCKED`：可以预览当前情报，但不能执行。
- `COMPLETED`：任务成功，可进入复盘。
- `FAILED`：上次执行失败，但仍可重试。
- `EXPIRED`：同层另一任务成功后关闭。

任务网络最多包含两个 INTEL 节点，分别对应两级情报权限；玩家可以完成 0–2 次。若首次阶段放弃 INTEL，后续仅剩一次情报行动机会，因此本 Run 无法取得第二级 `TOTAL INTEL`。

成功节点会持续改变后续防空体系：

| 任务 | 持久效果 |
|---|---|
| INTEL | 一次完成核实全部雷达坐标与型号，两次完成授权 `TOTAL INTEL`；不再维护额外的情报质量百分比 |
| STRIKE | 将后续任务的雷达扫描速率乘以 90%；两次累计为 81%，同时影响扫描动画与真实 Sensor 周期 |
| SEAD | 将后续雷达覆盖范围乘以 90%，最低为 55%；不影响扫描速度或最终火控增援 |
| COMMAND STRIKE | 将后续 Commander 协调降至 65%，削弱跨雷达 Contact 共享和联合跟踪能力 |
| FINAL STRIKE | 根据整个 Run 历史组装最终防空体系，成功后赢得本次 Run |

所有任务成功都会使 Enemy Alert 增加 2，失败增加 10；Alert 会按 `1 + Alert / 250` 扩大后续雷达范围。Enemy Adaptation 还会分析已经发生的飞行轨迹，针对地形利用、南北走廊和直达路线调整后续雷达部署；它不会读取尚未执行的未来航点。

这些奖励分别改变不同维度：INTEL 改变玩家掌握的信息，STRIKE 改变雷达扫描频率，SEAD 改变覆盖空间，COMMAND STRIKE 改变雷达网协同。任务类型不会强化 F-117 本体，也不会绕过“摧毁目标并撤离”的统一成功条件。

## 有限情报与 INTEL 权限

普通地图显示的是玩家掌握的雷达情报，而不是敌方真实状态：

- 未完成 INTEL 时，每部雷达有 90% 的确定性发现概率。
- 估计位置带有 `50–70 u` 的误差半径，覆盖范围存在 `±8%` 估算误差。
- 情报置信度固定落在 60%–88% 区间；`POSSIBLE` 信号不提供范围估计。
- 未定位信号只显示数量，不生成虚假精确坐标。

以上有限情报规则参数对所有任务一致，但每部雷达的遗漏与误差由任务 Seed 独立决定，因此相同 OPERATION CODE 与 Run 历史仍可复现。游戏不再维护会被权限层级覆盖的连续“情报质量”数值。

INTEL 权限由已完成的 INTEL 节点数量派生：

- `0/2`：有限雷达情报。
- `1/2`：后续任务准确显示全部雷达位置和类型，但不公开真实范围或敌方内部状态。
- `2/2`：正式解锁 `TOTAL INTEL`，可显示真实雷达扫描、Contact、Belief Map、Commander 目标和 Operator Utility。

开发环境或显式 `?ai-debug=1` 同样可以打开完整内部视图，但显示开关不改变任何任务计算或存档结果。

## 雷达与防空交战

防空网由三类具有真实差异的雷达组成：

| 类型 | 主要职责 | 特性 |
|---|---|---|
| Early Warning | 远程预警 | 覆盖大、波束宽，Contact 精度和火控贡献较低 |
| Acquisition | 搜索与目标获取 | 覆盖、扫描和跟踪能力均衡 |
| Fire Control | 近程火控与制导 | 覆盖较小、波束窄，但扫描快、Contact 精度和锁定贡献高 |

雷达不是“进入覆盖圈即发现”。只有扫描波束经过飞机且概率判定成功时才会生成带误差的 Radar Contact。探测概率受距离、机体朝向、地形遮蔽和动态天气共同影响。

STRIKE 的扫描速率修正同时作用于广域旋转速度、扇区摆扫相位和实际扫描周期。速率为 90% 时，波束角速度为基础值的 90%，实际扫描间隔变为 `基础周期 / 0.9`；它不会改变单次扫描的探测概率、覆盖范围或 Contact 精度。

每台 Radar Operator 根据自身或共享 Contact，在以下模式间选择 Utility 最高的动作：

- `WIDE_SEARCH`：360° 广域搜索。
- `SECTOR_SEARCH`：围绕可疑方位扇区摆扫。
- `FOCUSED_TRACK`：聚焦最近的高质量 Contact。

连续证据会推动 `UNDETECTED → SUSPECTED → TRACKED → LOCKED → MISSILE_INBOUND`。没有新 Contact 时跟踪质量下降；导弹来袭后必须在倒计时结束前切断足够多的新证据，否则飞机被摧毁。

每场任务最终准备完成后都会校验：至少一部 Fire Control 完整覆盖目标攻击区并保留 `20 u` 余量。该约束保证目标区存在火控威胁，但不保证飞机一定被发现。

## 敌方认知数据链

项目严格维护以下信息边界：

```text
Reality（飞机真实状态）
  → Radar Sensor（唯一可读取 Reality 的敌方模块）
  → Imperfect Contact（带误差观测）
  → Belief Map（概率位置估计）
  → Air Defense Commander / Radar Operator
  → Engagement（跟踪、锁定与导弹）
```

Belief Map 使用 `24×24` 概率网格，只融合 Radar Contact。Commander 只能读取 Awareness、Belief、雷达状态和协调修正，不能读取飞机真实位置，也不会在投弹后把目标区当成飞机位置。

## 环境、天气与航线成本

- Terrain 是静态山地遮蔽区。
- Weather Cell 由 Seed 生成，并随任务绝对时间确定性移动、改变范围、强度和类型。
- Cloud、Fog、Rain、Storm 分别使飞机减速 10%、15%、20%、30%；重叠时只取最强减速。
- 规划阶段提供带误差的 `T+30/60/90s` 天气预报。
- 相同 Seed 与相同任务时间会复现相同地图、雷达、目标和真实天气状态。

恶劣天气和地形能够降低探测概率，但天气减速也会延长雷达覆盖内的暴露时间。安全航线因此不是简单绕开所有覆盖，而是在情报误差、油量、遮蔽和任务时间之间求解。

## 地图与任务生成

战术地图坐标系固定为 `1000×1000 u`，网格间隔 `100 u`。插入点、东北撤离区和目标区火控覆盖规则构成稳定边界，其余主要内容由任务 Seed 生成：

| 内容 | 当前生成规则 |
|---|---|
| 地形 | 2–4 个静态山地区域；位置、宽高和探测遮蔽系数由 Seed 决定 |
| 天气 | 1–2 个动态单元；初始类型、位置、尺度、速度、强度、演化相位和周期由 Seed 决定 |
| 雷达 | 3–5 部，按 Early Warning → Acquisition → Fire Control 顺序循环生成，保证普通任务至少包含三种类型 |
| 目标 | 在地图中上部生成；进入 `58 u` 攻击半径后自动投弹 |
| 撤离区 | 固定在东北区域；雷达中心必须与其边界保持 `80 u` 净空，但雷达覆盖可以延伸至撤离区 |
| 有限雷达情报 | 每部雷达按固定基线和独立子 Seed 生成遗漏、`50–70 u` 位置误差与 `±8%` 范围误差 |

任务生成完成后依次应用 Enemy Alert、SEAD 覆盖修正、STRIKE 扫描修正、COMMAND STRIKE、Enemy Adaptation 和 Final Strike 增援，最后执行撤离区净空与目标区 Fire Control 覆盖校验，并基于最终真实雷达重新生成玩家侧有限情报。因此同一节点在 Run 早期预览和真正解锁后，基础地图相同，但防空部署可能因玩家此前行动而改变。

## OPERATION CODE 与确定性生成

`OPERATION CODE` 是整个 Run 的根 Seed，作用类似 Minecraft 的世界种子：相同字符串与相同游戏版本会生成相同的任务网络和基础任务内容，但本项目使用自己的轻量算法，并非 Minecraft 的生成算法。

```text
玩家输入 OPERATION CODE
  → FNV-1a 32 位字符串哈希
  → Mulberry32 伪随机序列
  → 节点 Seed：<OPERATION CODE>:C<层>-<序号>
  → 任务内容流：<节点 Seed>:MISSION-CONTENT
  → 地形 / 天气 / 雷达 / 目标
  → 最终雷达部署对应的有限雷达情报
```

不同系统使用带命名后缀的独立确定性随机流，避免一个系统增加一次随机读取后整体扰乱其他系统：

- 雷达有限情报：`<节点 Seed>-M01:INTEL:<Radar ID>`。
- 天气预报误差：`<节点 Seed>:FORECAST:<Weather ID>:<预测秒数>`。
- Final Strike 增援：`<节点 Seed>-M01:FINAL-DEFENSE`。
- 雷达探测判定：`<节点 Seed>-M01:<Radar ID>:<Scan Count>`。

Seed 决定基础世界和确定性随机结果，不会抹掉玩家行为。实际航点、飞行时间、任务成败、Enemy Alert、已选任务、情报权限和 Enemy Adaptation 会继续改变后续状态。完整复现一次任务需要相同 OPERATION CODE、相同 Run 历史、相同航线操作和相同任务时间演进；仅输入相同代码不代表不同玩法过程必然得到相同结局。

## 预览、复盘与进度保存

- 锁定节点的“预览任务”使用当前 Run 状态生成只读地图；完成其他任务后再次预览，部署可能随持久效果变化。
- 成功撤离时冻结任务快照，包括最终航线、飞机状态、天气、雷达、Contact、Belief、Commander 和 Operator。
- “复盘任务”默认显示任务视角，并可切换全景复盘查看冻结的敌方内部状态。
- Run、任务网络、当前 Mission 和成功复盘每秒保存到浏览器 `localStorage`。
- 刷新运行中的任务会继续执行，不会恢复为暂停。

## 代码结构

- `src/core`：确定性随机数等基础设施。
- `src/domain`：纯领域逻辑，包括航线、雷达、Contact、Belief、Commander、天气、Campaign 与适应系统。
- `src/game`：`RunState`、reducer、持久化和帧循环。
- `src/procedural`：由 Seed 生成任务与任务网络。
- `src/ui`：React 战术终端、只读情报/复盘 Workspace 和 Canvas 地图。
- `src/audio`：由领域事件驱动的 Web Audio 合成音效。
- `src/config`：地图、飞机、雷达和交战参数。

核心不变量：

- `RunState` 与 `MissionSession` 分离，Canvas 不持有领域状态。
- 只有 Radar Sensor 可以读取飞机真实状态，后续 AI 只能消费 Contact。
- 预览和复盘是只读视图，不修改当前任务或 Campaign。
- Seed 决定的内容必须与帧率无关并可复现。
- UI 显示权限不能反向影响雷达、Commander 或交战计算。

新增机制时应优先把纯计算放入 `domain`，由 reducer 组织状态演进，最后由 UI 消费结果；不要在 Canvas 或 React 组件中实现第二套游戏规则。

## 当前边界

- 仅适配桌面浏览器和鼠标操作。
- 暂未实现任务内雷达摧毁、反辐射导弹、实时 ELINT 测向、可变燃油载荷、外挂油箱、多存档槽或云端同步。
- 游戏不包含 Tactical Reward 或 Player Build；长期变化来自任务网络、情报、Enemy Alert 和敌方适应。
